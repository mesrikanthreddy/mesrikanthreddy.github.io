## Hashing: Many Categories, Few Buckets

<Convo
  lines={[
    { who: 'cherry', text: 'I have a categorical feature with a million possible values and my model runs out of memory.' },

    { who: 'sundu', text: 'Bucketing how?' },
    { who: 'sriku', text: 'A hash function sends each category to one of a smaller number of buckets. Google’s glossary example: 73,000 tree species, but only 200 appear in your data, so use maybe 500 buckets.' },
    { who: 'cherry', text: 'Two species in one bucket?' },
    { who: 'sriku', text: 'Sometimes, yes. Baobab and red maple could share one. That is a collision, and it is usually fine when it is rare.' },
  ]}
/>

## Hyperparameter: The Dials You Set

<Convo
  lines={[
    { who: 'cherry', text: 'My model has a learning rate, a batch size and a dropout rate. Which of those does it learn?' },
    { who: 'sriku', text: 'None. Those are hyperparameters: the variables that you, or a tuning service, adjust between training runs. The weights and biases it learns are the parameters.' },
    { who: 'sundu', text: 'So how do I find good settings?' },
    { who: 'sriku', text: 'The textbook way is a grid. A neater way, it turns out, is to pick randomly.' },
  ]}
/>

<Gif
  name="hyperparameter"
  alt="Two squares of trial points. Grid search tries nine points on a three by three grid, so only three distinct values along the one important axis, marked by a curve above. Random search tries nine random points, so nine distinct values along that axis. The picture is a toy illustration."
  caption="Fig. 75: Toy picture. Nine trials, three values on the axis that matters, or nine."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Random beats a grid? Surely not.' },
    { who: 'sriku', text: 'Bergstra and Bengio showed it, empirically and theoretically. The reason is that usually only a few hyperparameters matter for a given dataset, and a grid wastes most trials repeating the same values of the important ones.' },
    { who: 'cherry', text: 'Evidence?' },
    { who: 'sriku', text: 'They compared with a large earlier study that had configured neural networks and deep belief networks by grid and manual search. Random search found models as good or better within a small fraction of the computation time.' },
    { who: 'sundu', text: 'And with the same budget?' },
    { who: 'sriku', text: 'It found better models, by searching a larger, less promising configuration space.' },
  ]}
/>

<CaseStudy
  title="Random search for hyperparameters (Bergstra and Bengio, 2012)"
  stats={[
    { value: 'Same or better', label: 'Models found by random search, vs pure grid search' },
    { value: 'Small fraction', label: 'Of the computation time, for neural networks' },
  ]}
  winner="The abstract: “randomly chosen trials are more efficient for hyper-parameter optimization than trials on a grid.”"
  takeaway="When you cannot try everything, vary every dial at once instead of one at a time."
  source={{
    text: 'Bergstra and Bengio, “Random Search for Hyper-Parameter Optimization”, JMLR 2012. Free PDF.',
    href: 'https://www.jmlr.org/papers/volume13/bergstra12a/bergstra12a.pdf',
  }}
/>

**Real definition:** the variables that you or a hyperparameter tuning service adjust during successive runs of training a model. Parameters, in contrast, are the weights and biases the model learns. [Google’s glossary (Fundamentals): hyperparameter ↗](https://developers.google.com/machine-learning/glossary/fundamentals#hyperparameter)

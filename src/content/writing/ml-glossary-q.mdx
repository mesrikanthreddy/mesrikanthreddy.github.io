The Q-function predicts the expected return from taking an action in a state and then following a given policy. ## Quantile Bucketing: Every Bucket Gets Its Fair Share

<Convo
  lines={[
    { who: 'cherry', text: 'My income feature is wildly skewed. With equal-width bins, nearly everyone lands in the first one.' },
    { who: 'sriku', text: 'Quantile bucketing distributes a feature’s values into buckets so that each bucket contains the same, or almost the same, number of examples. Google’s figure divides 44 points into 4 buckets of 11 points each.' },
    { who: 'sundu', text: 'So the buckets have different widths.' },
    { who: 'sriku', text: 'Yes. Where data is dense, the buckets are narrow. Where it is sparse, they are wide.' },
  ]}
/>

<Gif
  name="quantile-bucketing"
  alt="Sixty toy values with a long right tail are placed on two number lines. With equal-width buckets, most values land in the first bucket and several buckets are empty. With quantile buckets, each of the six buckets holds about ten values."
  caption="Fig. 117: Toy skewed data. Equal widths crowd one bucket, quantiles share the load."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Do big models use this idea too?' },
    { who: 'sriku', text: 'In a surprising place: QLoRA, from Dettmers, Pagnoni, Holtzman and Zettlemoyer. Its 4-bit NormalFloat data type builds on quantile quantization, which ensures each quantization bin has an equal number of values assigned from the input tensor.' },
    { who: 'cherry', text: 'Why equal counts?' },
    { who: 'sriku', text: 'The paper calls quantile quantization information-theoretically optimal. It also says estimating quantiles is expensive, and that the cost can be avoided when the input tensors come from a distribution fixed up to a quantization constant. That is how they get a cheap data type for normally distributed weights.' },
    { who: 'sundu', text: 'What did that buy them?' },
    { who: 'sriku', text: 'QLoRA reduces memory enough to finetune a 65B parameter model on a single 48GB GPU while preserving full 16-bit finetuning task performance. Their Guanaco models reach 99.3% of ChatGPT’s performance level on the Vicuna benchmark, after 24 hours of finetuning on a single GPU. That benchmark figure is the authors’ own claim, so treat it as theirs.' },
  ]}
/>

**Real definition:** distributing a feature’s values into buckets so that each bucket contains the same (or almost the same) number of examples. [Google’s glossary: quantile bucketing ↗](https://developers.google.com/machine-learning/glossary#quantile-bucketing)

## Quantization: Same Brain, Fewer Bytes

<Convo
  lines={[
    { who: 'cherry', text: 'Everyone says "quantize the model". Quantize what, exactly?' },
    { who: 'sriku', text: 'Google calls quantization an overloaded term. It can mean implementing quantile bucketing on a feature, or transforming data into zeroes and ones. The meaning we want here is reducing the number of bits used to store a model’s parameters.' },
    { who: 'sundu', text: 'Like going from 32 bits down to 8?' },
    { who: 'sriku', text: 'The glossary example is 32-bit floating-point parameters converted to 4, 8 or 16 bits. It reduces compute, memory, disk and network usage, the time to infer a prediction and power consumption. The catch is that quantization sometimes decreases the correctness of the model’s predictions.' },
  ]}
/>

<Gif
  name="quantization"
  alt="A grid of blue cells represents a weight matrix. The cells shrink from 16-bit to 8-bit width while one gold column of outlier values keeps its full width. A memory bar next to it halves. A caption cites the LLM.int8() paper. The matrix is a toy example."
  caption="Fig. 118: Toy matrix. Shrink most numbers, protect the outliers."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Does the catch matter at big sizes?' },
    { who: 'sriku', text: 'LLM.int8(), by Dettmers, Lewis, Belkada and Zettlemoyer, tackles exactly that. Their Int8 matrix multiplication for transformers cuts the memory needed for inference by half while retaining full precision performance, and a 175B parameter 16/32-bit checkpoint can be loaded, converted to Int8 and used immediately without performance degradation.' },
    { who: 'cherry', text: 'What was the trick?' },
    { who: 'sriku', text: 'Emergent outlier features that dominate attention and predictive performance. They quantize most values vector-by-vector, and isolate the outlier dimensions into a 16-bit multiplication, while still more than 99.9% of values are multiplied in 8-bit.' },
    { who: 'sundu', text: 'And the payoff?' },
    { who: 'sriku', text: 'They say it makes models like OPT-175B and BLOOM usable on a single server with consumer GPUs.' },
  ]}
/>

<CaseStudy
  title="LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale (Dettmers et al., 2022)"
  stats={[

  ]}
  winner="The abstract: “cut the memory needed for inference by half while retaining full precision performance.”"
  takeaway="Most numbers can live in fewer bits. A handful of outliers decide whether the model still works, so find them and protect them."
  source={{
    text: 'Dettmers, Lewis, Belkada and Zettlemoyer, “LLM.int8(): 8-bit Matrix Multiplication for Transformers at Scale”, 2022. Free on arXiv.',

/>

**Real definition:** an overloaded term. One meaning is reducing the number of bits used to store a model’s parameters, for example converting 32-bit floating-point parameters to 4, 8 or 16 bits. Others are implementing quantile bucketing, and transforming data into zeroes and ones. [Google’s glossary: quantization ↗](https://developers.google.com/machine-learning/glossary#quantization)

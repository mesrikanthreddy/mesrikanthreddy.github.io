## Kernel Support Vector Machines: Bend the Problem Until It Is Straight

<Convo
  lines={[
    { who: 'cherry', text: 'My two classes are mixed in a circle. No straight line will separate them.' },
    { who: 'sriku', text: 'A kernel support vector machine, a KSVM, maps your data into a higher-dimensional space, then looks for the boundary that maximizes the margin between the classes.' },
    { who: 'sundu', text: 'How much higher?' },
    { who: 'sriku', text: 'Google’s glossary example: a dataset with a hundred features might be mapped internally into a million-dimension space. KSVMs train with a loss function called hinge loss.' },
  ]}
/>

<Gif

  caption="Fig. 87: Toy data. Lift it, and a flat boundary is enough."

<Convo
  lines={[
    { who: 'sundu', text: 'Where did people actually use them?' },
    { who: 'sriku', text: 'Text. Thorsten Joachims’ 1998 paper applied SVMs to text categorization. Text has more than 10,000 features, one per word, and that usually breaks learning algorithms.' },
    { who: 'cherry', text: 'Why did SVMs cope?' },
    { who: 'sriku', text: 'The paper argues that an SVM’s protection against overfitting does not depend on the number of features, only on the margin. It also found that there are very few irrelevant features in text, and that most categories are linearly separable.' },
    { who: 'sundu', text: 'So a kernel was not even needed?' },
    { who: 'sriku', text: 'Often a plain linear boundary was enough, which is the paper’s point. The kernel is a tool for when the data is bent. The paper reports substantial improvements over the best methods then, tested on the Reuters-21578 and Ohsumed collections.' },
  ]}
/>

<CaseStudy

**Real definition:** a classification algorithm that seeks to maximize the margin between positive and negative classes by mapping input data vectors to a higher-dimensional space; it uses the hinge loss. [Google’s glossary: Kernel Support Vector Machines (KSVMs) ↗](https://developers.google.com/machine-learning/glossary#kernel-support-vector-machines-ksvms)

## K-Fold Cross-Validation: Everyone Gets a Turn as the Test

<Convo
  lines={[
    { who: 'cherry', text: 'I only have 120 examples. Setting 20% aside as a test set leaves very little to train on.' },
    { who: 'sriku', text: 'Use k-fold cross-validation. Split the data into k equal groups. Train and test k times, and each time a different group is the test set while the rest train.' },
    { who: 'sundu', text: 'And the score?' },
    { who: 'sriku', text: 'After the k rounds you take the mean and standard deviation of your metric. Google’s example is 120 examples with k = 4, so four groups of 30 and four rounds.' },
  ]}
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Is there a best k?' },
    { who: 'sriku', text: 'Ron Kohavi studied it at Stanford. He compared cross-validation with the bootstrap in an experiment of over half a million runs of the C4.5 and Naive Bayes algorithms on real-world datasets.' },
    { who: 'cherry', text: 'And?' },
    { who: 'sriku', text: 'Leave-one-out, the extreme where k equals the number of examples, is almost unbiased but has high variance, so its estimates are unreliable.     { who: 'sundu', text: 'More folds is not better.' },

  ]}
/>

<CaseStudy
  title="Choosing k (Kohavi, 1995)"

**Real definition:** an algorithm for predicting a model’s ability to generalize to new data. The k refers to the number of equal groups the dataset is divided into; you train and test k times, with a different group as the test set each time. [Google’s glossary: k-fold cross validation ↗](https://developers.google.com/machine-learning/glossary#k-fold-cross-validation)

## K-Means: Find the Centres of the Crowds

<Convo
  lines={[
    { who: 'cherry', text: 'I have thousands of customers and no labels. How do I group them?' },
    { who: 'sriku', text: 'K-means, a popular clustering algorithm for unsupervised learning. It repeatedly finds the best k centre points, called centroids, and assigns each example to its closest centroid.' },
    { who: 'sundu', text: 'Best in what sense?' },
    { who: 'sriku', text: 'It picks centroid positions that minimize the sum of the squared distances from each example to its closest centroid.' },
    { who: 'cherry', text: 'And k-median?' },
    { who: 'sriku', text: 'A close relative. K-median minimizes the sum of the distances instead of the squared distances. That is the practical difference.' },
  ]}
/>

<Gif
  name="k-means"
  alt="Three clouds of toy points are coloured by the nearest of three diamond-shaped centroids. In each round the points are reassigned to their nearest centroid, and then each centroid moves to the middle of its points, until nothing changes."
  caption="Fig. 90: Toy data, k = 3. Assign, move, repeat."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Does it scale to the web?' },
    { who: 'sriku', text: 'D. Sculley at Google found the classic batch version too slow for user-facing applications that need results in a fraction of a second. His fix was mini-batch k-means: update the centroids from small random batches.' },
    { who: 'cherry', text: 'How much faster?' },
    { who: 'sriku', text: 'On the RCV1 news collection, with 781,265 training documents, the mini-batch method reached near-optimal values several orders of magnitude faster than full batch, and gave significantly better solutions than online stochastic gradient descent.' },
    { who: 'sundu', text: 'Real numbers for latency?' },
    { who: 'sriku', text: 'For small k it produced near-best cluster centres for nearly a million documents in a fraction of a CPU second, on a single ordinary 2.4 GHz machine. That makes real-time clustering practical.' },
  ]}
/>

<CaseStudy
  title="Web-scale k-means (Sculley, Google, 2010)"
  stats={[
    { value: '781,265', label: 'RCV1 training documents' },
    { value: 'Orders of magnitude', label: 'Faster than batch k-means to near-optimal values' },
    { value: '< 1 CPU second', label: 'For nearly a million documents, small k, one 2.4 GHz machine' },
  ]}
  winner="The abstract: mini-batch optimization “reduces computation cost by orders of magnitude compared to the classic batch algorithm while yielding significantly better solutions than online stochastic gradient descent.”"
  takeaway="You do not need every point to update the centres. A small random batch is enough."
  source={{
    text: 'Sculley (Google), “Web-Scale K-Means Clustering”, WWW 2010. Free PDF (hosted on a Northeastern University course page).',

  }}
/>

**Real definition:** a popular clustering algorithm that groups examples in unsupervised learning by iteratively determining the best k centroids and assigning each example to the closest one. [Google’s glossary: k-means ↗](https://developers.google.com/machine-learning/glossary#k-means) · [k-median ↗](https://developers.google.com/machine-learning/glossary#k-median)

## Vanishing Gradient Problem: Give the Signal a Shortcut

    { who: 'cherry', text: 'How deep?' },

  ]}

**Real definition:** the tendency for the gradients of early hidden layers of some deep neural networks to become surprisingly flat (low). Increasingly lower gradients result in increasingly smaller changes to the weights on nodes in a deep neural network, leading to little or no learning. [Google’s glossary: vanishing gradient problem ↗](https://developers.google.com/machine-learning/glossary#vanishing-gradient-problem)

## Variable Importances: Handle With Care

<Convo
  lines={[
    { who: 'cherry', text: 'My random forest gave me a ranked list of features. Can I just drop the ones at the bottom?' },

Google’s example is a decision tree for house prices, with size scoring 5.8, style 4.7 and age 2.5, so size matters most to that tree. The glossary adds that different variable importance metrics exist.' },
    { who: 'sundu', text: 'Are the scores always trustworthy?' },

  ]}

<Convo
  lines={[

    { who: 'sriku', text: 'Strobl, Boulesteix, Zeileis and Hothorn, in BMC Bioinformatics in 2007.     { who: 'cherry', text: 'How bad is unreliable?' },
    { who: 'sriku', text: 'In their simulation studies, the results were misleading, because suboptimal predictor variables could be artificially preferred in variable selection.     { who: 'sundu', text: 'Is there a fix?' },
    { who: 'sriku', text: 'They propose an alternative implementation of random forests that provides unbiased variable selection in the trees. Used with subsampling without replacement, the importance measures can be used reliably even when predictors vary in scale or number of categories. My animation uses made-up numbers, only to show the direction of the bias.' },
  ]}
/>

## Variational Autoencoder (VAE): Blur the Code, Get New Samples

<Convo
  lines={[
    { who: 'cherry', text: 'The autoencoder from Part A squeezes an image into a code and rebuilds it. Can I use it to make new images?' },
    { who: 'sriku', text: 'That is what a variational autoencoder, a VAE, is for. Google describes it as a type of autoencoder that leverages the discrepancy between inputs and outputs to generate modified versions of the inputs. It is useful for generative AI and is based on variational inference, a technique for estimating the parameters of a probability model.' },
    { who: 'sundu', text: 'What is different from a plain autoencoder?' },
    { who: 'sriku', text: 'The encoder does not output a single code. It outputs a description of a small cloud of codes, a mean and a spread, and the decoder works from a random sample from that cloud.' },
  ]}
/>

<Gif
  name="vae"
  alt="A toy digit 7 enters an encoder, which outputs a mean and a spread. Random samples scatter around the mean in a latent space panel. A decoder then rebuilds an image from one sample. A caption says the noise trick makes the sampling step trainable with ordinary stochastic gradient descent. The picture is a toy illustration."
  caption="Fig. 138: Toy picture. Encode to a cloud, sample from it, decode."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Where did VAEs come from?' },
    { who: 'sriku', text: 'Kingma and Welling, in Auto-Encoding Variational Bayes. They ask how to do efficient inference and learning in directed probabilistic models with continuous latent variables whose posteriors are intractable, on large datasets.' },
    { who: 'cherry', text: 'What was their contribution?' },
    { who: 'sriku', text: 'Two things. A reparameterization of the variational lower bound that yields an estimator you can optimize with standard stochastic gradient methods, and an approximate inference model, also called a recognition model, fitted to the intractable posterior using that estimator.' },
    { who: 'sundu', text: 'The reparameterization is the noise trick?' },
    { who: 'sriku', text: 'In practice, yes: write the sample as the mean plus the spread times random noise, so the randomness sits outside the network and gradients can flow through the rest. The abstract is theoretical, so I am not quoting a headline number for this one.' },
  ]}
/>

<CaseStudy
  title="Auto-Encoding Variational Bayes (Kingma and Welling, 2013)"
  stats={[
    { value: '2', label: 'Contributions: a reparameterized lower bound and a recognition model' },
    { value: 'Large datasets', label: 'The setting the algorithm is designed to scale to' },
  ]}
  winner="The abstract: “a reparameterization of the variational lower bound yields a lower bound estimator that can be straightforwardly optimized using standard stochastic gradient methods.”"
  takeaway="Make the randomness an input rather than a step inside the network, and a generative model becomes trainable with the usual tools."
  source={{
    text: 'Kingma and Welling, “Auto-Encoding Variational Bayes”, 2013. Free on arXiv.',
    href: 'https://arxiv.org/abs/1312.6114',
  }}
/>

**Real definition:** a type of autoencoder that leverages the discrepancy between inputs and outputs to generate modified versions of the inputs. Variational autoencoders are useful for generative AI. [Google’s glossary: variational autoencoder (VAE) ↗](https://developers.google.com/machine-learning/glossary#variational-autoencoder-vae)

## Vibe Coding: It Felt Fast. The Clock Disagreed.

<Convo
  lines={[
    { who: 'cherry', text: 'My teammate says they built the whole checkout page by describing it to a model and accepting everything.' },
    { who: 'sriku', text: 'That is vibe coding. Google’s glossary defines it as prompting a generative AI model to create software: your prompts describe the software’s purpose and features, and the model translates them into source code. The generated code does not always match your intentions, so it usually takes iteration.' },
    { who: 'sundu', text: 'Who named it?' },
    { who: 'sriku', text: 'Andrej Karpathy, in an X post describing it as a new kind of coding where you fully give in to the vibes. The glossary says the term originally implied an intentionally loose approach where you might not even examine the generated code, and that it has since come to mean almost any AI-generated coding.' },
  ]}
/>

<Gif
  name="vibe-coding"
  alt="A small terminal box shows a prompt asking a model to make a checkout page work, then a note that 214 lines were generated and accepted without review. Three bars compare speed: developers predicted AI would make them 24 percent faster, felt 20 percent faster afterwards, and were measured 19 percent slower. A caption names the METR trial. The terminal text is a toy illustration; the percentages are from the study."
  caption="Fig. 139: The terminal is a cartoon. The three percentages are from the study."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Is there any real measurement of how this feels versus how it performs?' },
    { who: 'sriku', text: 'The nearest thing is a randomized controlled trial by Becker, Rush, Barnes and Rein at METR. Sixteen experienced open-source developers completed 246 tasks in mature projects they had worked on for about five years on average. Each task was randomly assigned to allow or disallow early-2025 AI tools, mostly Cursor Pro with Claude 3.5 and 3.7 Sonnet.' },
    { who: 'cherry', text: 'And what happened?' },
    { who: 'sriku', text: 'Before starting, developers forecast that AI would reduce completion time by 24%. Afterwards they estimated it had reduced it by 20%. The measured result was that allowing AI increased completion time by 19%. Economics experts had predicted 39% shorter and machine learning experts 38% shorter.' },
    { who: 'sundu', text: 'So vibe coding is slow.' },
    { who: 'sriku', text: 'No, and I want to be precise. This trial studied experienced developers working on familiar code with AI assistance, not people vibe coding without review. It says nothing about novices or about prototypes, and tools have changed since early 2025. What it does show is that how fast something feels is not a measurement.' },
  ]}
/>

<CaseStudy

/>

**Real definition:** prompting a generative AI model to create software. That is, your prompts describe the software’s purpose and features, which a generative AI model translates into source code. The generated code doesn’t always match your intentions, so vibe coding usually requires iteration. [Google’s glossary: vibe coding ↗](https://developers.google.com/machine-learning/glossary#vibe-coding)

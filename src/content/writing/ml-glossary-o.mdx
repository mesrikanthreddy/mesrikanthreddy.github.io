## Out-of-Bag Evaluation: A Free Test Set Inside Every Forest

<Convo
  lines={[
    { who: 'cherry', text: 'A random forest trains hundreds of trees. Do I still need a separate validation set?' },
    { who: 'sriku', text: 'You can use out-of-bag evaluation: test each decision tree against the examples that were not used to train that tree. Google’s picture has each tree trained on about two-thirds of the examples and evaluated on the remaining third.' },
    { who: 'sundu', text: 'Does that replace cross-validation?' },
    { who: 'sriku', text: 'The glossary calls it a computationally efficient and conservative approximation of cross-validation. Cross-validation trains one model per round, 10 models for 10-fold, which we met in Part K. Out-of-bag evaluation trains a single model.' },
  ]}
/>

<Gif
  name="oob"
  alt="Three trees each draw a bootstrap sample from twelve numbered examples. Blue boxes are the examples a tree trained on, with a multiplier where an example was drawn more than once. Gold boxes marked out are the examples that tree never saw. A caption says each bootstrap sample leaves out about 37 percent of the examples. The draws are a toy example."
  caption="Fig. 108: Toy bootstrap. Gold means left out, so it can test that tree."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Who worked out the leftover share?' },
    { who: 'sriku', text: 'Leo Breiman at Berkeley, in a paper called Out-of-Bag Estimation. In bagging, each predictor is built on a bootstrap sample, and he notes that each bootstrap sample leaves out about 37% of the examples.' },
    { who: 'cherry', text: 'What are the leftovers good for?' },
    { who: 'sriku', text: 'His abstract says they can give much improved estimates of node probabilities and node error rates in decision trees, and nearly optimal estimates of generalization error for bagged predictors.' },
    { who: 'sundu', text: 'So the leftovers are a free validation set.' },
    { who: 'sriku', text: 'For each example, you score it using only the trees that never saw it. No second dataset and no extra training run.' },
  ]}
/>

<CaseStudy
  title="Out-of-Bag Estimation (Breiman)"
  stats={[
    { value: '37%', label: 'Of examples left out of each bootstrap sample' },
    { value: 'Nearly optimal', label: 'Estimates of generalization error for bagged predictors' },
  ]}
  winner="The abstract: “These left-out examples can be used to form accurate estimates of important quantities.”"
  takeaway="Bagging throws away a bit of data for every tree. Out-of-bag evaluation puts it to work."
  source={{
    text: 'Breiman, “Out-of-Bag Estimation”, Statistics Department, University of California, Berkeley. Free PDF.',
    href: 'https://www.stat.berkeley.edu/~breiman/OOBestimation.pdf',
  }}
/>

**Real definition:** a mechanism for evaluating the quality of a decision forest by testing each decision tree against the examples not used during training of that decision tree. It is a computationally efficient and conservative approximation of the cross-validation mechanism. [Google’s glossary: out-of-bag evaluation (OOB evaluation) ↗](https://developers.google.com/machine-learning/glossary#out-of-bag-evaluation-oob-evaluation)

## Overfitting: A Perfect Score on the Wrong Thing

<Convo
  lines={[
    { who: 'cherry', text: 'My training accuracy is 100 percent and my test accuracy is a disaster.' },
    { who: 'sriku', text: 'That is overfitting: creating a model that matches the training data so closely that it fails to make correct predictions on new data. Regularization can reduce it, and so can training on a large and diverse training set.' },
    { who: 'sundu', text: 'Can a network really memorize that much?' },
    { who: 'sriku', text: 'A famous paper tried the most extreme version of the question: replace the labels with random ones.' },
  ]}

<Convo
  lines={[

    { who: 'cherry', text: 'Even on ImageNet?' },

    { who: 'sriku', text: 'The paper says the effective capacity of the networks is sufficient for memorizing the entire dataset, and that fitting random labels takes only a small constant factor more training time. That is why a low training error alone tells you very little.' },

**Real definition:** creating a model that matches the training data so closely that the model fails to make correct predictions on new data. [Google’s glossary (Fundamentals): overfitting ↗](https://developers.google.com/machine-learning/glossary/fundamentals#overfitting)

## Oversampling: Make the Rare Class Less Rare

<Convo
  lines={[
    { who: 'cherry', text: 'One in five thousand of my transactions is fraud. The model just says "not fraud" every time.' },
    { who: 'sriku', text: 'Oversampling reuses the examples of a minority class in a class-imbalanced dataset to create a more balanced training set. Google’s example is a ratio of 5,000 to 1 in a million examples, which leaves only about 200 minority examples, so you reuse those 200 several times. That is the imbalance problem from Part I.' },
    { who: 'sundu', text: 'Any catch?' },
    { who: 'sriku', text: 'You need to be careful about overfitting, because you are showing the model the same few examples again and again.' },
  ]}
/>

<Gif
  name="oversampling"
  alt="Many blue majority dots fill a scatter plot, with seven red minority dots in one corner. New gold dots appear one at a time on the lines between neighbouring red dots until the rare class has fourteen extra synthetic points. The data is a toy example."
  caption="Fig. 110: Toy data. SMOTE adds new points between real rare examples."
/>

<Convo
  lines={[
    { who: 'sundu', text: 'Copying is the simple way. Is there a smarter way?' },
    { who: 'sriku', text: 'SMOTE, the Synthetic Minority Over-sampling Technique, from Chawla, Bowyer, Hall and Kegelmeyer in the Journal of Artificial Intelligence Research, 2002. Instead of copies it creates synthetic minority examples along the line segments joining a minority example to its k nearest minority neighbors. Their implementation used five.' },
    { who: 'cherry', text: 'And the results?' },
    { who: 'sriku', text: 'They tested with C4.5, Ripper and Naive Bayes, scoring by area under the ROC curve. A combination of over-sampling the minority class and under-sampling the majority class gave better performance in ROC space than only under-sampling the majority class, and better than varying the loss ratios in Ripper or the class priors in Naive Bayes.' },
    { who: 'sundu', text: 'Anything I should double-check?' },
    { who: 'sriku', text: 'My own advice, not the paper’s: on very imbalanced data, look at precision and recall as well as ROC, which is a story for Part P.' },
  ]}
/>

<CaseStudy
  title="SMOTE (Chawla, Bowyer, Hall and Kegelmeyer, 2002)"
  stats={[
    { value: '5', label: 'Nearest minority neighbours used in the authors’ implementation' },
    { value: '3', label: 'Classifiers tested: C4.5, Ripper and Naive Bayes' },
  ]}
  winner="The abstract: “a combination of our method of over-sampling the minority (abnormal) class and under-sampling the majority (normal) class can achieve better classifier performance (in ROC space) than only under-sampling the majority class.”"
  takeaway="Do not just copy the rare examples. Fill in new ones between them, and still guard against overfitting."
  source={{
    text: 'Chawla, Bowyer, Hall and Kegelmeyer, “SMOTE: Synthetic Minority Over-sampling Technique”, Journal of Artificial Intelligence Research 16, 2002. Free on arXiv.',
    href: 'https://arxiv.org/abs/1106.1813',
  }}
/>

**Real definition:** reusing the examples of a minority class in a class-imbalanced dataset in order to create a more balanced training set. Contrast with undersampling. [Google’s glossary: oversampling ↗](https://developers.google.com/machine-learning/glossary#oversampling)

## Chai-Stall Recap

| Term | The chai-stall version | Plain meaning |
| --- | --- | --- |
| One-shot learning | See it once, recognize it again | Learn a class from a single example |
| Optimizer | Same hill, smarter steps | An implementation of gradient descent, such as Adam |
| Out-of-bag evaluation | A free test set inside every forest | Test each tree on examples it never saw |
| Overfitting | A perfect score on the wrong thing | Matches the training data, fails on new data |
| Oversampling | Make the rare class less rare | Reuse or create minority-class examples |
